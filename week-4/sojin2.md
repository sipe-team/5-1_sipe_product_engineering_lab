# 4주차: PRD — (기능/개선 제안 제목)

> **한 줄 요약**: 첫 진입 시 빈 화면에서 느끼는 '막막함'을 데이터 기반 샘플 제공으로 해결하여, 목표 등록 전환율(57% → 80%)을 개선하고 신규 유저의 안착을 돕는다.

## 분석 대상
- **서비스**: Buckie
- **선정한 페인포인트** (3주차에서 검증): 가입 직후 무엇을 쓸지 모르는 이탈(Zero State) 및 비회원 이용 시 데이터 유실 우려.

---

## 1. 배경 및 문제 정의 (Why)

### 문제 상황
(구체적으로 어떤 상황에서 어떤 문제가 발생하는지)
사용자는 **"버킷리스트를 기록하고 싶다"**는 목적을 가지고 앱을 다운로드한다. 하지만 짧은 온보딩 직후 아무것도 없는 비어있는 화면을 마주하게 되면, 무엇을 어떻게 적어야 할지 몰라 **막막함**을 느낍니다. 이 '빈 페이지 증후군'은 사용자가 앱의 가치를 경험하기도 전에 이탈하게 만드는 가장 큰 원인이 된다.


### 영향받는 사용자
- **신규 유입 사용자**: 앱 설치 후 첫 1분 이내의 경험이 전체 경험을 결정함.
- **라이트 유저**: 기록 습관이 들기 전이라 가이드가 없으면 쉽게 포기함.

### 근거
- **앱 업데이트 분석(3주차)**: 레포브에서 장소 검색, 링크 첨부 등 **'기록 입력 방식의 편의성'** 고도화를통해 초기 기록 장벽 문제를 해결하고 있음.
- **앱 리뷰 및 트렌드**: "데이터가 날아갈까 봐 무섭다"는 피드백과 소셜 로그인 선호 경향 확인.

+추가
- **높은 유실률**: 목표 추가 시도(`goal_add_start`) 대비 저장 완료(`goal_add_save`) 비율이 **약 57%**에 불과함. 즉, **유저 10명 중 4명은 입력 화면에서 막막함을 느껴 작성을 포기함.**
- **낮은 활성화**: 전체 신규 유입자(18명) 중 실제 목표를 1개라도 저장한 유저는 **5명(27%)**뿐임. 나머지 73%는 핵심 가치를 경험하지 못한 채 이탈함.
- **높은 충성도 역설**: 기존 유저의 `goal_detail_view`는 123건으로 매우 높음. 즉, **"첫 고비만 넘기면 앱을 계속 쓸 유저인데, 입구 컷이 너무 높은 상황"**임.

### 방치하면 생기는 비즈니스 영향
사용자가 데이터를 쌓지 않으면 앱을 다시 켤 이유(Retention)가 사라짐. 결국 실제 활성 유저(Retention)로 전환되지 않기 때문에, **유입된 사용자가 앱의 진정한 가치를 느끼기도 전에 이탈하는 악순환이 반복되어 서비스의 자생력이 상실된다.**

## 2. 목표와 성공 지표 (What + KPI)

### 목표 (Goal)
> 신규 사용자가 앱 설치 후 1분 이내에 첫 번째 버킷리스트를 등록하고, 안전하게 기록을 보관할 수 있는 상태를 만든다.

### 성공 지표 (KPI)

| **지표**                                  | **카테고리**     | **현재** | **목표**               |
| --------------------------------------- | ------------ | ------ | -------------------- |
| **목표 등록 전환율** (`start` 대비 `save`)       | Task Success | 57%    | **80%**              |
| **신규 유저 활성화율** (`first_open` 대비 `save`) | Activation   | 27%    | **50%**              |
| **평균 참여 시간**                            | Engagement   | 7분 36초 | 유지 또는 소폭 감소 (입력 효율화) |

**핵심 지표:  **목표 등록 전환율 (57% → 80%)**
이게 핵심인 이유: Buckie의 핵심 가치는 '기록'에 있으며, 데이터를 생성하는 순간이 서비스에 안착하는 가장 중요한 시점(Aha-Moment)이기 때문

## 3. 사용자 경험 변화 (Before → After)

### Before (현재)
이서아(22세, 대학생)는 매년초 작성하는 버킷리스트 목표를 기록하고 관리하려고 Buckie를 다운받았다.
앱을 실행했는데, 짧은 온보딩이 지나가고 빈 화면에 덩그러니 목표 추가버튼이 뜬다.
"어.. 뭐부터 써야하지? 한 달에 책 한 권? 아니면 여행??? 나중에 쓰자." 하고 앱을 나가게된다.

### After (개선 후)
이서아는 Buckie를 다운 받는다.
앱 첫 진입 시 온보딩 마지막에 "다른 사람들은 이런 목표를 세워요"라는 추천 키워드(예: 한 달에 책 한 권 읽기)를 보고 마음에 드는 항목을 터치해 1초 만에 첫 목표를 만든다.
목표를 등록하는게 쉬우니 원하는 목표를 빠르게 세팅하고 기록하기위해 주기적으로 앱에 들어오게 된다.
+"이 기록을 안전하게 보관할까요?"라는 안내에 안심하며 소셜 로그인하도록 유도한다. (추후)

## 4. 솔루션 접근법 (How - 개괄)

### 접근 방식
> 샘플 데이터로 '심리적 허들'은 낮추면서 쉽게 행동하게 만든다.
그 행동의 결과를 보호해야 한다는 명분으로 로그인을 제안(추후)
### 핵심 아이디어
1. **Quick-Pick 샘플 라이브러리**: '운동', '여행', '독서' 등 가장 대중적인 버킷리스트 5~10개를 카드 형태로 제공.
2. **플레이스홀더 고도화**: 입력창에 "예: 2026년에 유럽 일주 가기" 같은 구체적인 가이드 텍스트 삽입.
3. **단계별 입력 유도**: 제목만 입력해도 저장이 가능하도록 하고, 상세 설명은 나중에 쓰도록 유도.

### 기술적/디자인적 고려사항
- 추천 리스트는 서버 없이 로컬 JSON으로 우선 구현하여 초기 로딩 속도 최적화.
- 소셜 로그인 API 연동 시 기존 로컬 DB(SQLite/Realm 등)와의 동기화 로직 정교화 필요.

## 5. ICE Score

| **후보 아이디어**         | **설명**       | **Impact** | **Confidence** | **Ease** | **ICE Score** | **판단**      |
| ------------------- | ------------ | ---------- | -------------- | -------- | ------------- | ----------- |
| **목표 샘플 템플릿**       | 인기 목표 원클릭 추가 | 9          | 8              | 6        | **432**       | **채택(MVP)** |
| **입력 가이드(Tooltip)** | 입력창 내 도움말 제공 | 6          | 4              | 4        | **96**        | V1 후보       |
| **AI 목표 추천**        | 관심사 기반 자동 생성 | 8          | 5              | 9        | **360**       | 보류          |
### 선택한 아이디어

> **목표 샘플 템플릿**
- **선택 이유**: 파이어베이스 데이터 분석 결과, 목표 작성을 시작(`goal_add_start`)한 유저의 **42.5%가 중도 이탈**하는 심각한 병목 구간이 확인되었다.
- **전략적 적합성**: '막막함'을 느끼는 유저에게 직접 타이핑하는 수고 대신 **'선택지'**를 제공하는 것이 이탈률을 낮추는 가장 즉각적이고 강력한 해결책(Impact 9)이라고 생각한다. 1인 개발자로서 서버 통신 없이 로컬 데이터만으로도 빠르게 구현 가능하다는 점(Ease 6)에서 가장 효율적인 MVP 모델로 판단했다.
### 선택하지 않은 아이디어
- **B. 입력 가이드(Tooltip)** (V1 후보)
  - **제외 이유**: 점수는 준수하지만, 툴팁은 사용자가 '무엇을 쓸지' 결정한 후에 '어떻게 쓸지'를 도와주는 보조 수단이다. 현재 Buckie의 핵심 문제는 **'무엇을 쓸지 몰라 시작조차 못 하는 것'**이므로, 툴팁보다는 샘플을 직접 제공하는 라이브러리 기능의 우선순위가 더 높다고 판단하여 다음 스프린트로 미루었다.
- **C. AI 목표 추천** (보류)
  - **제외 이유**: 임팩트는 높을 수 있으나, 1인 개발 환경에서 프롬프트 엔지니어링 및 API 연동에 드는 공수(Ease 9)가 너무 크다. 또한, 현재 샘플 데이터만으로도 충분히 가설 검증이 가능한 상태에서 기술적 복잡도를 높이는 것은 리스크가 크다고 판단하여 장기 검토 과제로 보류했다.

## 6. 범위와 우선순위 (Scope)

| **범위**           | **내용**                                         |
| ---------------- | ---------------------------------------------- |
| **MVP**          | 메인 화면 Zero State에 샘플 목표 카드 5개 노출, 원클릭 복사/등록 기능 |

| **Out of Scope** | 친구 팔로우 기능, 유료 템플릿 판매                           |

## 7. 리스크와 대안 (Risks)

### 리스크 1: 샘플 목표의 낮은 매력도
- **시나리오**:  비회원으로 목표를 10개 만들었는데 로그인을 하면 기존 데이터가 사라지는 경우.
- **완화**: 가입 로직 수행 전 로컬 DB 데이터를 임시 저장하고, 가입 완료 시점에 서버 DB로 Bulk Insert 수행.

### 리스크 2: 소셜 로그인 연동 시 데이터 꼬임
- **시나리오**: 추천해 주는 목표들이 너무 뻔해서 사용자가 흥미를 느끼지 못함.
- **완화**: 공개 데이터 기반으로 가장 많이 검색되는 키워드(여행, 운동, 공부) 위주로 큐레이션.
