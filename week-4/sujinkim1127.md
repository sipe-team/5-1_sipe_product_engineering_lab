# 4주차: PRD — 비로그인 구매 전환 플로우 개선: "회원가입 후 원래 포스트로 돌아가기"

> **한 줄 요약**: 비로그인 사용자가 유료 포스트 구매를 시도한 뒤 회원가입을 완료하면 홈 화면으로 빠져 원래 포스트를 찾을 수 없는 문제를, 가입/인증 완료 후 자동으로 해당 포스트로 복귀시키는 플로우로 개선한다.

## 분석 대상

- **서비스**: 포스타입(Postype) — 웹
- **선정한 페인포인트**: 비로그인 상태에서 유료 글 구매 시도 → 회원가입/이메일 인증 → 홈으로 리다이렉트되어 원래 포스트를 다시 찾을 수 없음 → 구매 전환 실패 및 신규 유저 이탈

---

## 벤치마킹

### 참고 서비스 1: 리디

앱은 원래 보던 페이지로 돌아가기 가능. 웹은 불가능

포스타입은 앱은 로그인해야지만 본문 조회 가능

- 어떻게 풀었는지
  - 카카오 회원가입의 카카오 앱으로 인증 후 되돌아가면 보던 화면 그대로
  - 이메일로 가입할 경우 이메일 인증을 크롬으로 완료한 후 앱 열기 버튼 존재
- 내 PRD에 반영할 점
  - “앱 열기” 패턴을 MVP에 포함시키기
- 차별화할 점
  - 앱 열기가 아닌 “이전 페이지로 돌아가기” 버튼으로 고도화하기

### 참고 서비스 2: 봄툰

- 어떻게 풀었는지
  - 이메일 인증을 한 페이지에서 진행한 후 가입이 완료되면 “이전 페이지로 돌아가기” 버튼 존재
- 내 PRD에 반영할 점
  - 컨텍스트 전환 0회로 볼 수 있는 최적의 UX
  - “이전 페이지로 돌아가기” 문구 차용하기

## 셀프 리뷰에서 발견한 구멍

1. **MVP 범위가 과대했음 → 2개 핵심 태스크로 축소**: MVP를 "이메일 가입 경로 한정 + returnURL + 인증 확인 버튼"으로 축소하고, 소셜 로그인 대응은 V1으로 이동.
2. **성공 지표가 추정치에 의존 → Task Success 기반 구체화**: "회원가입 후 5분 내 첫 구매 완료율 10~15% → 40%"라고 썼으나, 현재 해당 퍼널 데이터 자체가 수집되지 않는 상태에서 추정치에 의존. 핵심 지표를 "회원가입 완료 → 원래 포스트 도달률"이라는 직접 측정 가능한 Task Success 지표로 변경하고, 구매 완료율은 후속 지표로 분리.
3. **크리에이터 측 영향이 누락 → Revenue 이해관계자 리스크 추가**: 구매 전환율 개선은 크리에이터 수익에 직결되지만, 수수료 정책(13%+발견수수료 17%)과의 충돌 가능성을 고려하지 않았음. 전환율이 올라가면 발견수수료 적용 대상 거래도 늘어날 수 있어, 크리에이터가 "전환은 좋아졌지만 수수료가 더 붙는다"고 느낄 리스크 추가.

## 피드백 반영

| 피드백 분류                                              | 반영 내용                                                       |
| -------------------------------------------------------- | --------------------------------------------------------------- |
| "MVP에 소셜 로그인까지 넣으면 범위가 너무 넓다"          | MVP를 이메일 가입 경로 한정으로 축소, 소셜 로그인은 V1으로 이동 |
| "경쟁사 벤치마킹이 구체적이면 설득력 올라감"             | 리디·봄툰 사례를 근거 섹션과 ICE Score에 전면 반영              |
| "인증 확인 버튼 문구가 기능 중심이라 사용자 관점이 아님" | "인증 확인" → "인증 확인하고 포스트로 돌아가기"로 변경          |

## 벤치마킹으로 강화한 부분

- **리디 사례**: 카카오 가입 시 원래 화면 즉시 복귀가 작동 → 소셜 로그인 returnURL 전달이 업계 표준임을 근거로 확보. ICE Score 아이디어 A의 Confidence를 8 → 9로 상향.
- **봄툰 사례**: 같은 페이지 내 인증 완료 + "이전 페이지로 돌아가기" 버튼으로 앱 전환 0회 달성 → V2 목표로 인증코드 입력 방식(앱 전환 0회) 추가. 또한 "이전 페이지로 돌아가기"라는 사용자 중심 문구를 차용하여 버튼 레이블 개선.
- **3사 비교를 통해 포스타입의 차별화 포인트 발견**: 리디·봄툰은 "원래 페이지 복귀"까지가 범위이지만, 포스타입 PRD는 "복귀 → 구매 완료"까지의 end-to-end 전환을 성공 지표로 설정하여 비즈니스 임팩트 측정 범위가 더 넓음.

## 1. 배경 및 문제 정의 (Why)

### 문제 상황

포스타입에서 신규 사용자가 유료 콘텐츠를 처음 구매하기까지의 여정은 다음과 같다:

1. 트위터(X) 등 외부 SNS에서 작가의 포스타입 링크를 클릭
2. 비로그인 상태로 포스트 미리보기 확인 → 유료 부분을 읽기 위해 "구매" 클릭
3. 로그인/회원가입 화면으로 이동
4. 회원가입 진행 (이메일 입력 → 이메일 인증 필요)
5. **이메일 인증 완료 후 홈 화면으로 이동됨**
6. 원래 보려던 포스트의 URL이나 제목을 기억하지 못함
7. 포스트를 다시 찾지 못하고 이탈

핵심 문제는 **5번 단계**에서 발생한다. 회원가입과 이메일 인증이라는 다단계 프로세스를 거치는 동안 원래 포스트의 컨텍스트(URL)가 유실되어, 가입을 완료한 사용자가 구매 의향이 있던 포스트로 복귀할 수 없다.

### 영향받는 사용자

- **직접 영향**: 비로그인 상태에서 유료 포스트 구매를 처음 시도하는 신규 사용자 전원
- **간접 영향**: 해당 포스트를 판매하는 크리에이터 (구매 전환율 저하로 인한 수익 감소)
- **규모 추정**: 포스타입은 매월 약 400만 건의 콘텐츠 거래가 발생하며, 외부 SNS(특히 트위터)에서의 유입이 핵심 채널이다. 외부 유입 사용자 중 비로그인 비율을 보수적으로 20%만 잡아도, 월 수십만 건의 잠재 구매 시도가 이 플로우를 거칠 수 있다.

### 근거

**앱 스토어 리뷰 분석(2024~2026)에서의 간접 근거:**

- App Store(3.5점/5), Google Play(3.6점/5)의 낮은 평점
- "로딩이 느리고 웹이 더 빠르다"는 리뷰에서 앱↔웹 전환 과정의 UX 결함이 반복적으로 지적됨
- 네이버 로그인 시 에러 후 백지 상태가 되는 등, 인증 플로우에서의 컨텍스트 유실 문제가 산발적으로 보고됨
- 나무위키에서 "앱에서 모바일 웹으로 전환 시 다른 사용자 계정으로 전환되는 사고"가 기록 — 인증 플로우의 상태 관리가 취약함을 시사

**경쟁사 벤치마킹 근거:**

- **리디**: 카카오 가입 시 원래 화면으로 즉시 복귀. 이메일 가입 시 크롬에서 인증 후 "앱 열기" 버튼 제공. 소셜 로그인 returnURL 전달이 업계 표준임을 증명.
- **봄툰**: 이메일 인증을 같은 페이지 내에서 완료, 가입 완료 시 "이전 페이지로 돌아가기" 버튼 존재. 앱 전환 0회로 컨텍스트 유실 가능성 자체를 제거. 가장 진보적인 패턴.
- **포스타입**: 복귀 수단 자체가 없음. 경쟁사 대비 뒤처진 상태.

**업데이트 노트 분석(2025.10~2026.04)에서의 근거:**

- 25회 업데이트 중 76%가 "서비스 안정성과 앱 성능을 개선했어요"라는 동일 문구
- 신규 기능 4건은 전부 캐릭터톡·오픈 채널·프리미엄 관련 — 회원가입/구매 전환 플로우 개선은 한 번도 언급되지 않음
- 사용자가 요청한 책갈피, 이어보기 등 "원래 위치로 돌아가기" 계열 기능이 2년간 방치

**기술 블로그 분석에서의 근거:**

- 회원가입 후 returnURL 리다이렉트는 기술적으로 기본적인 구현 — 현재 미구현은 기술 난이도가 아닌 제품 기획의 우선순위 문제

**이 문제가 스토어 리뷰에 직접 등장하지 않는 이유:**

- 이 시나리오의 사용자는 "가입을 막 완료한 신규 유저"이므로 리뷰를 남길 만큼의 플랫폼 관여도가 형성되기 전에 이탈
- 전형적인 "조용한 이탈(Silent Drop-off)" 패턴 — 분노가 아닌 귀찮음으로 이탈하므로 데이터에 잡히지 않음

### 방치하면 생기는 비즈니스 영향

1. **신규 유저 첫 구매 전환율(Activation Rate) 저하**: 가입까지 했는데 구매를 못 한 사용자는 "다음에 해야지" → 대부분 돌아오지 않음
2. **크리에이터 수익 감소**: 외부 SNS에서 유입된 잠재 구매자가 전환되지 않으면 크리에이터의 포스타입 수익이 줄고, 이는 크리에이터 이탈로 이어질 수 있음
3. **수수료 인상 반감 악화**: 2025년 3월 수수료를 13%+발견수수료 17%로 인상한 상황에서, 전환율까지 낮으면 크리에이터에게 "수수료는 올리고 구매는 안 되게 만든다"는 이중 불만 형성
4. **캐릭터톡 등 신규 기능의 효과 제한**: AI 캐릭터톡으로 신규 유입을 늘려도, 유료 콘텐츠 구매 퍼널이 막혀 있으면 매출로 전환되지 않음
5. **경쟁사 대비 열위 고착**: 리디·봄툰은 이미 해결한 문제를 포스타입만 방치하면, 신규 유저가 경쟁 플랫폼과 비교 시 "포스타입은 불편하다"는 인식이 굳어짐

## 2. 목표와 성공 지표 (What + KPI)

### 목표 (Goal)

> 비로그인 사용자가 유료 포스트 구매를 위해 회원가입을 완료한 후, 추가 탐색 없이 해당 포스트로 즉시 복귀하여 구매를 완료할 수 있는 상태를 만든다.

### 성공 지표 (KPI)

| 지표                                    | HEART 카테고리 | 현재(추정)        | 목표     | 비고                                    |
| --------------------------------------- | -------------- | ----------------- | -------- | --------------------------------------- |
| 회원가입 완료 → 원래 포스트 도달률      | Task Success   | ~0% (홈으로 빠짐) | 90% 이상 | **핵심 지표** — 직접 측정 가능          |
| 회원가입 후 5분 내 첫 구매 완료율       | Task Success   | 미측정            | 40% 이상 | 후속 지표 — MVP 배포 후 베이스라인 측정 |
| 비로그인 유입 → 가입 → 구매 퍼널 완주율 | Adoption       | 미측정            | 30% 이상 | 퍼널 전체 — 이벤트 트래킹 세팅 후 추적  |

**핵심 지표**: **회원가입 완료 → 원래 포스트 도달률**

이 지표가 핵심인 이유: 현재는 이 수치가 사실상 0%(홈으로 리다이렉트)이므로, MVP가 제대로 작동하면 0% → 90%라는 극적인 변화가 측정되어야 한다. 측정 방법이 명확하고(returnURL 파라미터가 있는 가입 → 해당 URL 페이지뷰 발생 여부), 추정이 아닌 실측이 가능하다. 구매 완료율은 포인트 충전 등 다른 변수가 개입하므로 후속 지표로 분리했다.

## 3. 사용자 경험 변화 (Before → After)

### Before (현재)

> 대학생 민지(22)는 트위터에서 좋아하는 일러스트 작가가 올린 포스타입 링크를 클릭했다. 작가의 유료 일러스트 모음이 3,000원에 판매되고 있었다. 미리보기 3장이 너무 마음에 들어 "구매하기"를 눌렀더니 로그인 화면이 나왔다. 포스타입 계정이 없어서 이메일로 회원가입을 진행했다. 이메일 인증 메일이 날아왔고, 메일 앱으로 이동해서 인증 링크를 클릭했다. 인증이 완료되자 포스타입 홈 화면이 떴다. "그 일러스트 어디 있었지?" 검색을 시도했지만 작가 닉네임을 정확히 기억하지 못했다. 트위터로 다시 가서 원래 트윗을 찾으려 했지만 타임라인이 이미 밀려 있었다. 결국 "나중에 찾아봐야지"라고 생각하고 앱을 닫았다. 그 "나중에"는 오지 않았다.

### After (개선 후)

> **경로 ① — 앱 내 "인증 확인" 버튼 사용 (MVP)**
> 민지는 동일하게 트위터에서 링크를 클릭하고, 유료 포스트를 보고 "구매하기"를 눌렀다. 로그인 화면에서 이메일로 회원가입을 진행했다. 이메일 인증 화면이 나왔고, 화면 중앙에 "인증 메일을 보냈어요. 메일함을 확인해주세요"라는 안내와 함께 **"인증 확인하고 포스트로 돌아가기"** 버튼이 보였다. 민지는 메일 앱에서 인증 링크를 클릭한 뒤 다시 포스타입 앱으로 돌아와 해당 버튼을 눌렀다. 버튼을 누르자 **아까 보고 있던 일러스트 모음 포스트로 바로 이동**되었다. 포인트 충전 후 3,000원을 결제하고 일러스트를 감상했다.
>
> **경로 ② — 브라우저 인증 페이지에서 복귀 (V1)**
> 또는 메일 앱에서 인증 링크를 클릭하면 브라우저에 인증 완료 페이지가 열리는데, 여기에 **"포스타입 앱에서 보기"** 버튼이 있다. 이 버튼을 누르면 앱이 열리면서 원래 포스트로 바로 이동된다.

## 4. 솔루션 접근법 (How - 개괄)

### 접근 방식

> 비로그인 상태에서 구매를 시도한 시점의 포스트 URL을 서버 세션에 보존하여, 회원가입·이메일 인증 완료 후 해당 URL로 자동 리다이렉트한다.

### 핵심 아이디어

1. **returnURL 세션 저장**: 비로그인 사용자가 "구매하기"를 누른 시점에 현재 포스트 URL을 서버 세션에 저장. 가입 완료 후 해당 URL로 리다이렉트. (OAuth state 파라미터가 아닌 서버 세션을 사용하여 소셜 로그인 콜백에서의 유실 방지)

2. **이메일 인증 대기 화면에 "인증 확인하고 포스트로 돌아가기" 버튼 추가**: 사용자가 메일 인증 후 앱으로 돌아와 버튼을 누르면 서버에 인증 상태를 확인하고, 성공 시 세션의 returnURL로 이동. 버튼 문구에 "포스트로 돌아가기"를 명시하여 사용자의 진짜 목적(콘텐츠 복귀)을 반영. (봄툰의 "이전 페이지로 돌아가기" 문구 패턴 차용)

### 기술적/디자인적 고려사항

- SpringBoot API 서버에 returnURL을 세션에 저장하는 로직 추가 (세션 만료: 최소 30분)
- "인증 확인하고 포스트로 돌아가기" 버튼은 수동 클릭 방식으로 구현 (자동 polling 대비 서버 부하 최소)
- `returnURL`의 보안: 포스타입 도메인 내부 상대 경로(`/@creator/post/12345`)만 허용하는 화이트리스트 검증 (Open Redirect/XSS 방지)
- 트위터 인앱 브라우저(WebView) → 포스타입 웹 → 가입 플로우에서도 세션이 유지되는지 별도 QA 필요

> **A. returnURL 세션 저장 + "인증 확인하고 포스트로 돌아가기" 버튼 (이메일 가입 한정)**

### 선택하지 않은 아이디어

- **B·C (V1)**: 인증 웹페이지 앱 열기 버튼(B)과 소셜 로그인 대응(C)은 각각 리디의 이메일 경로·카카오 경로를 벤치마킹한 것. 둘 다 MVP 이후 1~2스프린트 내 추가하면 가입 경로의 90% 이상을 커버 가능.
- **D (V2)**: 봄툰의 인증코드 방식은 앱 전환 0회라는 최적 UX이나, 포스타입의 현재 인증 시스템(링크 클릭 방식)을 근본적으로 전환해야 하므로 공수가 큼. 장기적으로는 이 방향이 좋아 보인다.
- **E (보조)**: ICE 336으로 나쁘지 않지만 근본 해결이 아닌 폴백 수단. V1에서 B와 함께 배포하면 "리다이렉트 실패 시 안전망" 역할.
- **F (V2)**: Impact 최고(10)이지만 결제·정산 시스템 전체 재설계가 필요해 현실적으로 가장 늦은 단계.

## 7. 리스크와 대안 (Risks)

### 리스크 1: returnURL 파라미터 보안 취약점

- **시나리오**: 악의적 사용자가 returnURL에 외부 피싱 사이트 URL을 삽입하여 Open Redirect 공격 시도
- **완화**: returnURL을 서버 측에서 포스타입 도메인 내부 상대 경로만 허용하도록 화이트리스트 검증. 절대 URL이 아닌 상대 경로(`/@creator/post/12345`)만 허용

### 리스크 2: 소셜 로그인 OAuth 콜백에서 세션 유실 (V1 단계)

- **시나리오**: 네이버/구글/애플 OAuth 인증 과정에서 여러 차례 리다이렉트 발생 시 서버 세션이 만료되거나 쿠키가 유실
- **완화**: MVP에서는 이메일 가입 경로로 한정하여 이 리스크를 회피. V1에서 OAuth 경로별 QA를 충분히 수행한 뒤 배포. 세션 만료 시간을 30분 이상으로 설정

### 리스크 3: 크리에이터 수수료 체감 불만 증가

- **시나리오**: 전환율이 올라가면 포스타입 내부 검색/추천을 통하지 않고 외부 링크에서 직접 유입→구매하는 비율이 높아짐. 이때 발견수수료(17%)가 적용되는 기준이 불명확하면, 크리에이터가 "전환이 좋아졌는데 수수료가 더 많이 붙는다"고 느낄 수 있음
- **완화**: 외부 SNS 직접 유입 → 구매 경로에 발견수수료가 적용되지 않음을 명확히 안내. 전환율 개선 효과를 크리에이터 대시보드에서 수치로 보여주어 긍정적 인식 형성

### 리스크 4: 트위터 인앱 브라우저 호환성 문제

- **시나리오**: 트위터(X) 앱의 인앱 브라우저에서 포스타입 웹 → 회원가입 시 세션 쿠키가 제대로 유지되지 않거나, Custom URL Scheme이 작동하지 않을 수 있음
- **완화**: MVP에서는 앱 내 플로우(인증 확인 버튼)를 우선하므로 인앱 브라우저 의존도가 낮음. V1에서 주요 인앱 브라우저(트위터, 인스타그램, 카카오톡) 환경별 QA 수행

## 8. 열린 질문 (Open Questions)

- 현재 비로그인 사용자의 "구매하기" 버튼 클릭 → 가입 완료 → 실제 구매까지의 퍼널 데이터가 수집되고 있는가? 이벤트 트래킹이 없다면 MVP 배포 전 GA/Amplitude 이벤트부터 설정해야 함.
- 이메일 인증 없이 가입을 완료하고 구매까지 한 뒤, 이메일 인증을 나중에 요구하는 "지연 인증(Lazy Verification)" 방식은 포스타입의 결제/정산 정책상 허용 가능한가? (허용되면 ICE 아이디어 D보다 빠른 대안이 될 수 있음)
- 리디의 "앱 열기" 버튼이 원래 보던 콘텐츠(책 상세 페이지)로 바로 이동하는지, 앱 홈으로 보내는지 실제 확인 필요. 후자라면 포스타입 PRD의 "포스트 직접 도달"이 명확한 차별점.
- 봄툰의 이메일 인증이 인증코드 입력 방식인지, 인라인 polling 방식인지 확인 필요. 포스타입의 현재 인증 시스템(링크 클릭)을 코드 입력으로 전환하는 백엔드 공수 사전 확인 필요.
- 앱 내 인앱 브라우저(트위터 WebView)에서 가입 플로우를 시작한 경우, 인증 완료 후 포스타입 앱으로의 전환이 아닌 "해당 브라우저에서 계속 보기" 옵션도 필요한가?
