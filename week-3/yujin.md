# 3주차: 공개 데이터로 프로덕트 읽기

## 분석 대상

- **서비스**: 뱅크샐러드 (Banksalad Co., Ltd.)
- **분석한 기능**: 자산관리 앱 → 종합 금융·건강 플랫폼 전환 (마이데이터 + 보험 진단 + 대출 비교 + 앱테크)
- **서비스 유형**: B2C 앱

---

## 2주차에서 발견한 페인포인트

1. **금융사 연동 안정성** — 스크래핑 기반 연동이 금융사 UI 변경이나 서버 불안정 시 즉시 끊기는 구조적 취약점이 있다.
2. **자산관리에서 금융 상품 판매로의 전환 과정에서의 정체성 혼란** — "내 편에서 중립적으로 관리해주는 앱"이라는 포지셔닝이 대출·보험 중개로 이동하면서 신뢰 균열 가능성이 있다.

---

## 공개 데이터 분석

- **사용한 소스**: Apple App Store 리뷰 (직접 수집) / 뱅크샐러드 기술 블로그
- **소스 선정 이유**: B2C 앱이므로 앱스토어 리뷰가 실사용자 목소리를 가장 직접 반영. 연동 안정성 이슈는 언론 이용자 인터뷰로, 정체성 혼란 이슈는 커뮤니티로 교차 검증.

### 내 페인포인트와 겹치는 피드백

**페인포인트 1: 금융사 연동 안정성**

> "새로운 뱅크샐러드에 대해 말씀 남겨주셨군요. 어떤 점이 불편하셨는지... 특히 연동 역시 원활하지 않으신 것 같아" — 구글플레이 리뷰에 대한 뱅크샐러드 공식 답변 (2024)

→ 뱅크샐러드 공식 답변에 "연동 불편"이라는 표현이 반복 등장한다는 것 자체가, 연동 문제가 고객센터에 반복 접수되는 주요 민원임을 회사 스스로 간접 시인하는 근거다.

> "뱅크샐러드를 초창기부터 사용했는데 서비스 연동 에러 발생 빈도가 잦아져 앱을 점점 안 쓰게 된다" — 이용자 C씨 (위키리크스한국)
>
> "주식계좌를 연동하는데 서비스 오류가 발생해서 30분을 허비했다" — 이용자 D씨 (위키리크스한국)

→ **근거**: 연동 실패가 단순 불편이 아닌 이탈 트리거임을 실제 이용자 목소리로 확인.  
→ **추론**: 이탈하는 사용자는 토스, 카카오페이 등 연동 안정성이 높은 경쟁앱으로 이동하는 패턴이 반복된다.

---

**페인포인트 2: 자산관리 → 금융상품 판매 플랫폼 전환의 정체성 혼란**

> "뱅크샐러드 개선에 도움 되고자 앱에 뜨는 팝업 설문조사에 응했는데 앱과 전혀 관계없는 유전자 검사 설문이었다" — 이용자 E씨 (위키리크스한국)

→ **근거**: 기존 기능 삭제 + 무관한 서비스 확장이 동시에 발생하면서 "이게 자산관리 앱인가 건강 앱인가"라는 정체성 혼란이 실 사용자들 사이에서 반응이 나오고 있는 것으로 보인다. 
→ **추론**: 뱅크샐러드가 빠르게 수익 모델을 다각화하는 과정에서, 기존 핵심 기능 완성도가 희생되었을 가능성이 높다. 생명연금 총액이나 보험 해지 환급금 정보 연동 등 기존에 확인 가능했던 서비스가 갑자기 없어져 소비자들의 불만도 이어졌다.

## 종합 판단

> 이 기능(자산관리 → 금융·건강 종합 플랫폼 전환)은 **부분적 성공 / 개선 중**이다.

**근거:**

1. **(공개 데이터 — 강한 근거)** 앱스토어 별점 4.1 / 2만 1천 개 리뷰는 사용자 기반이 확보됐음을 보여준다. 연동 에러·기존 서비스 삭제 불만은 핵심 기능 품질에 오류가 있었음을 볼 수 있었다.

2. **(기업 공개 정보 — 강한 근거)** 2025년 MAU +22%, 매출 +77%, 2025년 2분기 최초 분기 흑자 달성이라는 숫자는 플랫폼 전환이 비즈니스 지표상 성공하고 있음을 보여준다. 기술 블로그에서 API 성공률 90% → 99% 개선을 공식 발표한 것은 연동 안정성 문제를 인지하고 해결 중인 것으로 보임.

3. **(종합 판단)** 매출·MAU 지표로 보면 성공이지만, 사용자 경험 지표로 보면 개선 중이다. "자산관리 앱"에서 "금융 중개 플랫폼"으로의 BM 전환은 매출을 견인했으나, 초기 핵심 가치였던 "중립적 자산 조회" 경험이 희생되는 과정에서 구형 사용자 이탈이 발생했다. 신규 기능(보험 진단, 앱테크)으로 신규 유저를 유입하면서 전체 MAU를 늘리는 방향으로 대응하고 있다.

**한계:**

- MAU 절대 수치를 공개하지 않아, 전환 성공을 정확히 정량화하기 어렵다.
- 앱스토어 업데이트 노트가 모두 동일 문구여서 구체적 기능 변화를 추적할 수 없다.
- 보험 진단 서비스 50만 유저가 기존 자산관리 유저의 전환인지, 신규 유입인지 외부에서 판별 불가하다.

## 내가 PM이라면 다음에 뭘 할 것인가?

> "금융 중개 플랫폼"으로의 전환이 매출을 견인하고 있지만, 기존 사용자의 "중립적 자산 조회" 가치 훼손이 이탈을 만들고 있다.
>
> 나라면 **핵심 자산 조회 기능의 품질을 다시 높이면서 금융 상품 추천을 맥락 기반으로 통합**하는 방향으로 제품의 요구사항을 맞추려고 할 것 이다. "대출 비교가 튀어나오는 앱"이 아니라 "내 자산 현황을 보다 보니 자연스럽게 더 나은 선택을 제안받는 앱"
