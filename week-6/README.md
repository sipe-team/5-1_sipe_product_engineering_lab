# 📅 6주차: 최종 발표 — 6주간의 여정을 하나의 케이스 스터디로

## 드디어 마지막입니다

> **"내가 분석하고, 검증하고, 제안한 모든 것을 5-7분 안에 전달할 수 있는가?"**

6주간 해온 것들을 돌아보면:

```
2주차: 페인포인트를 발견했다 (User Journey Map)
3주차: 그게 진짜 문제인지 검증했다 (공개 데이터)
4주차: 해결책을 제안했다 (PRD v1)
5주차: 다듬고 근거를 강화했다 (PRD v2 + 벤치마킹)
```

이제 이걸 **하나의 스토리** 로 엮어서 발표합니다.

---

## 발표 형식

| 항목 | 내용 |
|------|------|
| **발표 시간** | 1인 5-7분 (엄수) |
| **Q&A** | 발표 후 2~3분 |
| **발표 순서** | 모임에서 결정 (지원순 또는 랜덤) |
| **자료 형식** | 자유 (슬라이드, 노션, md 파일 화면 공유 등 뭐든 OK) |

---

## 발표에 반드시 포함하면 좋을 5가지

형식은 자유이지만, **아래 5가지는 포함** 해주면 좋을 것 같아요~!
슬라이드로 만든다면 5-7장이면 충분합니다.
하지만 본인의 스타일대로 자유롭게 발표하셔도 괜찮습니다!
(혹시 여유가 되신다면, PRD 문서대로 됐을 때의, UI/UX 사진도 있으면 더 좋을 것 같아요!)

### 1. 분석 대상

> "나는 어떤 서비스의 어떤 기능을 분석했다"

- 서비스명, 분석한 기능, 왜 이 서비스를 골랐는지 한 줄

### 2. 발견한 핵심 페인포인트

> "이 기능에는 이런 문제가 있다"

- 2주차 User Journey Map에서 발견한 페인포인트
- 여러 개 발견했더라도 **가장 핵심적인 1~2개**만 발표

### 3. 검증 근거

> "이 문제는 나만 느끼는 게 아니다"

- 3주차에서 찾은 공개 데이터 근거 (앱 리뷰, 기술 블로그, 채용 공고 등)
- "30개 리뷰 중 12개에서 동일한 불만이 나왔다" 같은 숫자가 있으면 좋아요
- 자사 서비스라면: 외부 추론 vs 내부 현실의 갭도 공유

### 4. 제안한 해결책

> "내가 이 제품의 Product Engineer라면 이렇게 하겠다"

- PRD의 핵심 솔루션 요약 (디테일 말고 큰 그림)
- Before → After 시나리오 (한 문장씩이라도)
- MVP 범위 (이게 뭐가 작고 뭐가 큰지)
- ICE Score와 핵심 근거
- (시간이 되면) 벤치마킹 사례 1개

### 5. 배운 것 / 혹은 느낀 점

> "이 미션을 통해 내가 가장 크게 배운 한 가지"

- 사고방식의 변화, 새로 알게 된 프레임, 실무에 적용할 계획 등
- **최소 두 가지.**

## 발표 팁

**시간 관리가 가장 중요해요.**

5-7분은 생각보다 짧아요. 리허설을 한 번만 해보면 "아 이건 빼야겠다"가 보여요.

- 슬라이드 1장에 30초-1분이 적당
- 글자를 빽빽하게 쓰지 말고, **핵심 문장 1~2개 + 말로 설명**
- "자세한 내용은 PRD를 참고해주세요"로 넘기면 돼요. 다 말하려고 하지 않아도 됩니다
- 7분이 넘어가면 타이머가 울립니다 (제가 관리)

**발표가 부담되는 분들에게:**

- 슬라이드 안 만들어도 돼요. `week-5/{username}.md` 파일을 화면 공유하면서 핵심만 짚어도 충분합니다
- 발표를 잘하는 게 아니라, **"내가 왜 이렇게 판단했는가"를 설명하는 게 핵심** 이에요
- 정답은 없어요. 6주간의 사고 과정 자체가 발표의 가치입니다

---

## Q&A 가이드 (듣는 사람을 위한)

발표가 끝나면 2~3분 Q&A 시간이 있어요. 질문이 안 떠오르면 이런 걸 물어보면 좋아요:

- "그 페인포인트를 처음 발견한 순간이 언제였어요?"
- "MVP를 그 범위로 정한 이유가 뭐예요? 더 작게 쪼갤 수는 없었나요?"
- "벤치마킹한 서비스와 본인 제안의 가장 큰 차이는 뭐예요?"
- "실무에서 이 PRD를 실제로 제안해볼 계획이 있어요?"
- "다시 한다면 다르게 접근할 부분이 있어요?"

## 회고: KPT (발표 전부 끝난 후)

모든 발표가 끝나면, 각자 **한 줄씩** 돌아가면서 공유해주세요 (1인 1분):

| 항목 | 질문 |
|------|------|
| **K**eep | 이 미션에서 계속 가져가고 싶은 사고방식/습관 하나 |
| **P**roblem | 가장 어려웠거나 아쉬웠던 점 하나 |
| **T**ry | 앞으로 실무에서 시도해보고 싶은 것 하나 |

| 마무리 | 수고했습니다 + 블로그 발행 권장 + 단체 캡처 | 5분 |

## 발표 후에 해주시면 좋은 것 (선택)

### 블로그 글 발행

6주간의 분석을 블로그에 정리해서 올리면 **그 자체가 포트폴리오** 가 됩니다.

"나는 OO 서비스를 6주간 분석했고, 이런 페인포인트를 발견했고, 이런 해결책을 제안했다"
— 이런 글이 기술 블로그에 있으면, 이직 면접에서 "프로덕트 관점의 사고를 보여주는 근거"가 돼요.

형식 자유이지만, 발표 자료를 그대로 글로 풀어도 충분해요.

### GitHub에 최종 정리

`week-5/{username}.md`가 이미 PRD v2로 완성되어 있으니, 발표 후 마지막으로 다듬어서 최종본으로 남겨두세요. 나중에 다시 꺼내볼 수 있는 기록이 됩니다.

## 마지막으로 여기까지 오신 여러분들에게...

> **6주 전, "이 기능은 왜 존재하는가?"라는 질문에서 시작했습니다.**
>
> 그 질문 하나로 페인포인트를 발견하고, 데이터로 검증하고, 해결책을 제안하고, 동료의 피드백으로 다듬는 과정을 경험했어요.
>
> 이 과정이 바로 **Product Engineer가 일하는 방식** 입니다.
>
> 코드를 잘 짜는 것도 중요하지만, **"왜 이걸 만들어야 하는가"를 묻고, 근거를 가지고 제안하는 능력** — 이게 여러분의 커리어에서 점점 더 큰 차별점이 될 거예요.
>
> 6주간 고생 많으셨습니다. 발표, 즐겨주세요!
