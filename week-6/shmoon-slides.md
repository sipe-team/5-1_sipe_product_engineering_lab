## 2주차 — 분석 대상

### 네이버 금융 · 증권사 리서치 리포트 탐색

**왜 골랐나**
- 매수/매도 직전의 **고관여 행동**
- AARRR로 Activation–Retention–Revenue를 모두 통과하는 길목

**역산 분석으로 본 존재 이유**
> 네이버는 리포트를 "정보 신뢰 허브"로 만들어
> 검색 트래픽 → 네이버페이증권 거래로 흘리고 싶었다

→ 단순 정보가 아니라 **퍼널의 마지막 직전 단계**

## 세 가지 질문

| 질문 | 답 |
|---|---|
| **저작권 리스크는?** | 법무 검토가 MVP 게이트<br>통과 못 하면 코드 한 줄 못 씀 |
| **누가 만드는데?** | "네이버가 만들어야 함"<br>외부에서 검증 불가 |
| **KPI는 어떻게 보지?** | 네이버 내부 로그 없이<br>측정 불가 |

<br>

> **PRD의 주어가 "네이버"였다.**

---

## 같은 문제, 다른 풀이

| | v1 | v2 |
|---|---|---|
| 풀려는 문제 | 정보 수집 비용 | **그대로** |
| 주체 | 네이버 | **DARTshot 팀(나)** |
| 데이터 | 증권사 PDF (저작권) | **DART OpenAPI (공공·무료)** |
| 형태 | 네이버 내부 기능 | **독립 웹 서비스** |
| KPI 측정 | 내부 로그 필요 | **GA로 직접 측정** |

> v1 → v2는 PRD를 다듬은 게 아니라 **폐기**한 것

---

## 왜 Chrome Extension이 아니었나

| | Extension | 웹 서비스 ✅ |
|---|---|---|
| 호환성 | Chrome 전용 | 모든 브라우저 |
| 안정성 | 네이버 DOM 깨지면 같이 깨짐 | 독립적 |
| 설치 | 스토어 마찰 | URL 한 번 |
| KPI | 스토어/로그 분리 | GA 단일 |

<br>

> Extension은 "남의 사이트에 붙어사는" 구조
> 웹 서비스는 사용자가 **직접 방문하는 목적지**

## DARTshot — Before

박민준 (32세, 직장인 투자자), 삼성전자 실적 발표 다음 날

```
네이버 금융 → "실적 증감률은 어디?"
  → DART 이동 → 기업코드 검색
  → 사업보고서 PDF (100페이지)
  → Ctrl+F "영업이익"
  → 다시 네이버 → 5분 경과
  → 결국 유튜브 "삼성전자 실적 정리" 검색
```

---

## DARTshot — After

`dartshot.kr` 에서 "삼성전자" 입력 → **30초**

```
삼성전자 (005930)

📊 실적 요약 (2024 Q4)
매출    79.1조  QoQ +12%   YoY +8%
영업이익  6.5조   QoQ +130%  YoY 흑자전환
최근 4분기 추이:  ▼ ▼ ▲ ▲  (회복세)

📋 최근 공시 (최신 5건)
자기주식 취득 결정     3시간 전
분기보고서 제출        어제
최대주주 지분 매각     2일 전
```

설치 X · 로그인 X · 저작권 리스크 0
