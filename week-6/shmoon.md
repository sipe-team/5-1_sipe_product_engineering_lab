# 6주차 최종 발표 — "왜 존재하는가"에서 "왜 안 만들어졌는가"까지

> **케이스 스터디**: 네이버 금융 리서치 → DARTshot
> **6주의 한 줄 요약**: 기능을 분석하다 보니, 만들어지지 않은 이유가 더 중요했다.

---

| # | 슬라이드 | 시간 | 핵심 메시지 |
|---|---------|------|-----------|

## 1. 시작 — 한 장의 질문

> **"실적 발표 다음 날, 박민준은 왜 DART 대신 유튜브를 볼까?"**

이 질문에서 6주가 시작됐습니다.
처음엔 "UX가 안 좋아서"라고 답했는데, 끝날 때쯤엔 답이 완전히 달라져 있었어요.

---

## 2. 분석 대상 — 네이버 금융 리서치 (2주차)

**왜 이 기능을 골랐는가**
- 투자자가 매수/매도 직전에 "근거를 빨리 확보"하려는 고관여 행동
- AARRR로 쪼갰을 때 Activation–Retention–Revenue를 모두 통과하는 길목

**역산 분석으로 본 이 기능의 존재 이유**
- 네이버는 리포트를 "정보 신뢰 허브"로 만들어 검색 트래픽을 거래(네이버페이증권)로 흘리고 싶었다
- 즉, 단순 정보 제공이 아니라 **퍼널의 마지막 직전 단계**

> 핵심 KPI 후보: 리포트 탭 진입률 → 상세 열람률 → 관심종목 등록률
> 여기서 어디가 새고 있는지를 다음 주에 본다

---

## 3. 공개 데이터로 검증 (3주차)

**소스**: 앱스토어 리뷰 / 네이버 D2 / IR 자료 / 채용 공고

**관찰된 페인포인트**
1. PDF 원문 의존 — "목표주가만 보고 싶은데 4페이지를 열어야 함"
2. 증권사 의견 비교 부재 — "BUY/HOLD 갈리는데 나란히 못 봄"
3. 오래된 리포트 신호 부족 — "작년 리포트가 상단에 뜸"
4. 행동 연결 단절 — 리포트 → 매수까지 앱 이동 필요

**채용 공고에서 본 신호**
- "Growth PM", "AI 금융 데이터 분석" 채용 진행 중
- **"증권 리포트 NLP/ML 엔지니어" 채용은 없음**
- → 회사도 알고 있는데, **저작권 문제로 파싱 자동화에 손을 못 대고 있다**는 가설

> 결론: "부분적 성공". 트래픽은 있는데 핵심 태스크가 무너져 있음.

---

## 4. PRD v1 — 카드형 요약 (4주차)

**솔루션**
- 리포트 목록 카드에 [BUY/HOLD] [목표주가] [상승여력] 자동 파싱 표시
- 동일 종목 복수 증권사 의견 비교 테이블

**핵심 KPI**
- "리포트 탭 PDF 미클릭 이탈률 70~80% → 50%"

**ICE 1위였던 이 안이 — 왜 폐기됐을까?**

발표 핵심 한 줄: **"내가 스스로에게 물었더니 답이 없었다."**

세 가지 질문이 무너뜨렸어요:

| 질문 | 답 |
|---|---|
| 저작권 리스크는? | 법무 검토가 MVP 게이트 — 통과 못 하면 코드 한 줄 못 씀 |
| 누가 만드는데? | "네이버가 만들어야 함" — 내가 검증할 수 없음 |
| KPI는 어떻게 보지? | 네이버 내부 로그 없이는 측정 불가 |

→ **PRD의 주어가 "네이버"였다**. 외부에서 가설을 검증할 방법이 없었다.

---

## 5. v1 → v2 전환 — 폐기의 순간 (5주차) ⭐

> 5주차 가이드의 한 줄: "내 PRD를 처음 보는 엔지니어가 받으면 바로 작업을 시작할 수 있는가?"

**나는 이 질문에 "아니오"라고 답했다.**

### 같은 문제, 다른 풀이
- 풀려는 문제: "정보 수집 비용 과다" — **그대로 유지**
- 풀이의 주체: 네이버 → **DARTshot 팀(나)**
- 데이터 소스: 증권사 PDF (저작권 있음) → **DART OpenAPI (공공·무료·재배포 허용)**
- 형태: 네이버 내부 기능 → **독립 웹 서비스**

### 왜 Chrome Extension이 아니라 웹 서비스였나

| 비교 | Extension | 웹 서비스 (선택) |
|---|---|---|
| 호환성 | Chrome 전용 | 모든 브라우저 |
| 안정성 | 네이버 DOM 깨지면 같이 깨짐 | 독립적 |
| KPI | 스토어/로그 분리 | GA 단일 |

> Extension은 "남의 사이트에 붙어사는" 구조. 웹 서비스는 사용자가 직접 방문하는 목적지.

### 이 슬라이드의 발표 한 마디
> "v1 → v2는 PRD를 다듬은 게 아니라 **폐기**한 겁니다.
> 5주차에서 가장 어려웠던 건 '내가 잘 썼다고 생각한 PRD를 버리는 것'이었어요."

## 6. DARTshot — 같은 문제, 새 주체

### Before
박민준 → 네이버 금융 → DART 이동 → 기업코드 검색 → PDF 열기 → Ctrl+F → 다시 네이버 → 5분 경과 → 결국 유튜브로

### After
박민준 → `dartshot.kr`에 "삼성전자" → 30초 안에 카드

```
삼성전자 (005930)

📊 실적 요약 (2024 Q4)
매출    79.1조  QoQ +12%  YoY +8%
영업이익  6.5조  QoQ +130%  YoY 흑자전환
최근 4분기 추이: ▼ ▼ ▲ ▲ (회복세)

📋 최근 공시 (최신 5건)
자기주식 취득 결정     3시간 전
분기보고서 제출        어제
최대주주 지분 매각     2일 전
```

### MVP (셀프리뷰 후 한 번 더 줄이기)
- 종목명 검색 → **실적 요약 카드** 하나
- 공시 카드는 V1으로 (가설 검증은 실적카드만으로도 가능)

### 핵심 지표
- 7일 재방문율 35% — "습관형 도구"가 됐는지의 신호

### 벤치마킹 (Playwright로 직접 검증)
- 토스증권: 공시 보려면 로그인 필수, DART 외부 이동
- 카카오페이증권: 웹은 계좌 개설 랜딩만, 종목 분석 = 앱 전용
- DART: 기업코드 기반 검색, 실적 계산 없음
- → **종목명 한 번에 실적 자동 계산 + 공시 분류**는 시장 공백

## 7. 6주 회고 — KPT

### Keep — 가져갈 사고방식
- **"주어가 누구인가"** 를 PRD 첫 줄에 쓴다. 주어가 외부에 있으면 검증 불가.
- 리스크는 일반론(개발지연/마케팅) 말고 **이 솔루션 고유의 리스크**만 적는다.
- 벤치마킹은 링크만 걸지 말고 **직접 접속해서 캡처**까지 — 그래야 차별점이 보인다.

### Problem — 어려웠던 점
- ICE 점수가 가장 높았던 안이 가장 큰 함정이었다 — 점수는 "확신"이 아니라 "현재 가진 정보의 함수"
- v1을 버리는 결정은 5주차 마감 압박 속에서 가장 큰 용기가 필요했다
- v2 MVP가 v1보다 다시 커지는 자연스러운 관성 — 셀프리뷰를 v2에도 한 번 더 적용해야 했다

### Try — 다음에
- 회사 일에서도 PRD 쓰기 전 **"주어 점검"** 을 첫 단계로
- 솔루션이 떠오르면 **"이걸 1주 안에 못 만들면 무엇 때문인가"** 한 줄 적기 — 그게 진짜 리스크
- 실제로 dartshot.kr MVP 1주일 안에 띄우고 사이프 사람들에게 첫 사용자 받기
