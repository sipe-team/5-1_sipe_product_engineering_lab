# 5주차: PRD v2 — 리멤버 "포지션 제안" 발신자 투명성 + 추천 이유 공개

> **한 줄 요약**: "포지션 제안 드립니다" 알림이 AI 자동 추천인지 사람의 직접 제안인지 한눈에 구분되게 하고, 추천 이유를 함께 보여줘 기대-현실 괴리를 해소한다. 이를 통해 알림 OFF로 인한 이탈을 막고, 리멤버 Revenue의 기반인 "응답 가능한 활성 인재 풀"의 품질을 유지한다. 5주차에는 셀프 리뷰와 벤치마킹을 반영해 KPI 베이스라인 수집 계획과 리스크 완화 트리거를 수치 기반으로 구체화했다.

## 분석 대상

- **서비스**: 리멤버 (Remember) — B2C 직장인 명함/커리어 플랫폼
- **선정한 페인포인트** (3주차에서 검증): **"채용 제안 품질 문제 — 특히 AI 자동 추천을 '포지션 제안'으로 포장해 발신자 투명성이 깨지는 구조적 문제와, 사용자가 '왜 이 제안을 받았는지' 모르는 근거 불투명 문제"**

---

## 1. 배경 및 문제 정의 (Why)

### 문제 상황
리멤버 사용자는 "포지션 제안 드립니다"라는 제목의 알림을 받고 스카웃(헤드헌터/기업 인사팀의 직접 제안)으로 기대하며 앱을 연다. 그러나 링크를 따라가면 버튼이 "[지원하러 가기]"로 되어 있고, 실제로는 리멤버 AI가 프로필 기반으로 매칭해 자동 발송한 **지원 유도 메시지**인 경우가 많다.

이 구조적 괴리는 두 가지 피해를 낳는다. 첫째, 사용자가 수락 후 후속 연락이 없거나 인사팀에 직접 문의해야 "AI가 보낸 것이었다"는 사실을 알게 된다. 둘째, 이런 경험이 반복되면 사용자는 알림 자체를 꺼버리거나 앱을 삭제하고, 그 결과 **실제 헤드헌터의 진짜 제안도 닿지 않게 되어 Revenue 파이프라인 전체가 끊긴다.**

여기에 더해 사용자는 "왜 내가 이 제안을 받았는지" 근거를 볼 수 없다. 10년 전 재직 회사에서 다시 연락이 오거나, 직무·연차가 맞지 않는 제안이 반복되는데, 매칭 근거가 숨겨져 있어 사용자는 "시스템이 나를 모른다"는 결론에 도달한다. 이는 발신자 투명성 문제와 결합하여 신뢰 훼손을 가속한다.

### 영향받는 사용자
- **1차**: 리멤버에서 포지션 제안을 받는 직장인 사용자 (누적 500만 회원)
- **특히 영향이 큰 세그먼트**: **적극적 이직자는 아니지만 좋은 기회가 오면 확인할 의향이 있는 잠재 이직자** — 리멤버의 장기 Revenue 축이지만 품질 낮은 제안이 반복되면 가장 먼저 알림을 끄는 그룹
- **비즈니스 이해관계자**: 기업 채용 담당자, 헤드헌터, 리멤버 Revenue 팀

### 근거 (3주차 분석)
- **[Google Play, changseop Yeom 2025.12.19]** *"원티드에서 탈락한 기업으로부터 리멤버 AI 자동 제안을 받아 수락했습니다. 수락 후 아무 연락이 없어, 직접 인사 담당자에게 물어봤고, 그 담당자는 'AI 자동 제안이며, 리멤버 측에도 전달하겠다'고 답했습니다."*
- **[Google Play, sy park 2025.12.10]** *"ai추천받아서 회사 인사팀이 직접 보낸다는 거짓말을 함. 홍보용인가? 알고리즘 문제?"*
- **[Google Play, Terry Kim 2025.04.22]** *"10년 다녔던 전 직장 다시 다니라고 친절하게 써치펌에서 제안옴. 프로필 보지도 않고 제안을 남발."*
- **[Google Play, 김민정 2025.10.13, 21명 유용]** *"프라이빗 포지션 제안이있다고 톡이 와서 보내주신 링크나 버튼으로 들어가보면 항상 요청하신 페이지가 없다고 나와요."* — **21명 공감**은 광범위한 문제라는 신호
- **[브런치 분석글]** *"리멤버의 '포지션 제안'은 실제 헤드헌팅이 아니라 AI 기반 시스템을 통한 지원 유도 메시지에 불과하다. 메시지는 '포지션 제안 드립니다'(스카웃 느낌)이지만, 실제 버튼은 '[지원하러 가기]'(일반 지원)."* → 구조적 원인 규명
- **[Google Play, MJ Y 2026.03.21]** *"이것때문에 알림을 아예 꺼두고 있네요ㅠ"* — 알림 OFF가 이탈 경로로 작동
- **[기업 정보]** 2024 매출 684.6억(YoY +72.7%), 영업손실 42.1억 → AI 채용 매칭이 Revenue 엔진인데 사용자 신뢰 훼손 시 직접 타격

### 방치하면 생기는 비즈니스 영향
- **알림 OFF → Dead User 전환**: 알림을 끈 사용자는 실제 헤드헌터 제안도 놓친다. 핵심 가치 제안(Scout)이 선반 안쪽으로 밀려남
- **인재 풀 품질 저하**: 리멤버 Revenue는 "기업이 접근할 가치가 있는 활성 인재 풀"에 의존. 제안 수만 늘리는 것으론 풀 질 유지 불가
- **법적·평판 리스크**: "AI 발송을 헤드헌터 제안처럼 포장"은 표시·광고 투명성 논란으로 번질 수 있음. 커뮤니티/뉴스 확산 시 브랜드 타격
- **B2B NRR 영향**: 사용자 신뢰 저하 → 기업 고객 입장에서 "지원자 engagement 하락" → 갱신율 압박
- **리멤버 커넥트 전환 걸림돌**: 비즈니스 SNS(2026.03 출시)라는 신뢰 기반 레이어가 "또 AI가 사칭하는 거 아냐?" 의심 위에 세워지게 됨

## 2. 목표와 성공 지표 (What + KPI)

### 목표 (Goal)
> **"제안 알림을 받은 사용자가 열기 전부터 이것이 AI 추천인지 사람의 직접 제안인지 즉시 구분할 수 있고, 상세 화면에서는 '왜 이 제안을 받았는지' 근거까지 볼 수 있어, 기대-현실 괴리 없이 신뢰할 수 있는 제안만 선별해 응답하게 만든다."**

### 성공 지표 (KPI)

| 지표 | 카테고리 | 현재(추정) | 목표 |
|------|---------|-----------:|------:|
| 제안 상세 진입 후 **긍정 액션률** (지원/관심있음/나중에/질문하기) | Task Success | 베이스라인 수집 필요 | **현재 대비 ▲10%p** |
| 제안 알림 OFF 전환율 | Retention | 고위험군 추정 | **현재 대비 ▼30%** |
| 제안 알림 관련 부정 리뷰 비율 (투명성·사칭 키워드) | Happiness | 월 **~20%** (12+건/60건) | 월 **8% 이하** |
| "추천 이유" 영역 펼침률 (V1 이후) | Engagement | 신규 지표 | **40% 이상** |

**핵심 지표**: **알림 OFF 전환율 ▼30%**
알림이 살아있어야 리멤버의 핵심 수익 경로(Scout → 지원 → B2B 수수료)가 작동한다. 단기 지원 전환은 투명성 강화로 일시 하락할 수 있으므로 전환 수가 아닌 **알림 채널 생존**을 최우선 지표로 둔다. 부정 리뷰 감소, 긍정 액션률 상승은 이 지표가 움직인 뒤 뒤따를 2차 지표.

**긍정 액션 정의**: 단순 클릭이 아니라 신뢰가 있어야 일어나는 행동 — `지원하기`, `관심 있음`, `나중에 보기`, `제안자에게 질문하기`.

5주차 셀프 리뷰에서 베이스라인 수집 계획을 다음으로 구체화했다 — **MVP 배포 2주 전부터** "알림 OFF 전환율 / 제안 알림 관련 부정 리뷰 키워드 필터 쿼리 / 제안 상세 진입 후 긍정 액션 funnel"을 Revenue·CS 팀 운영 대시보드에 선배치하고, **최소 2주간 현황 수집** 후 MVP 10% 롤아웃 집단과 베이스라인 집단을 주 단위로 비교한다. 측정 주체는 Revenue 팀이 ownership을 갖고 Product가 funnel 설계를 보조한다.

## 3. 사용자 경험 변화 (Before → After)

### Before (현재)
> 민정은 금요일 오후 업무 중 "포지션 제안 드립니다" 푸시를 받는다. 10년 다닌 전 직장 스카웃이라는 알림 본문을 보고 놀라 앱을 연다. 상세 화면에는 기업 로고와 포지션이 있지만, 누가 왜 보낸 제안인지 명확하지 않고 버튼은 "지원하러 가기"다. 수락하고 며칠이 지나도 연락이 없다. 인사담당자에게 직접 문의하니 "리멤버 AI가 매칭한 것"이라는 답을 듣는다. 민정은 Google Play에 1점 리뷰를 남기고 **앱 알림을 전부 꺼버린다** . 3개월 뒤 진짜 헤드헌터가 찾았지만 알림이 꺼져 있어 닿지 않는다.

### After (MVP 적용)
> 민정은 푸시를 받는다. 타이틀이 **"🤖 AI 추천 포지션"** 으로 시작한다. 앱을 열자 상세 상단에 *"리멤버 AI가 프로필 기반으로 추천했어요. 기업의 직접 제안이 아닙니다."* 회색 배지가 명시되어 있다. 버튼도 "지원하러 가기"로 일관. 민정은 "아 이건 자동 매칭이구나"라고 납득한 상태로 JD를 읽고, 관심 없으면 무시한다. 다음 주 **"⭐ 헤드헌터 직접 제안"** 배지가 붙은 알림이 왔을 때는 더 비중 있게 연다.

### After V1 (추천 이유 공개 + 피드백)
> 민정은 AI 추천 상세 상단에서 **"이 제안을 받은 이유"** 영역을 펼친다. `프론트엔드 경력 5년 이상` / `React 경험` / `B2B SaaS 산업군`이 매칭 근거로 표시된다. 조건 하나(산업군)가 맞지 않아 **"관심 없음"** 을 누르고 "산업군이 맞지 않음" 을 선택한다. 다음부터 유사 오매칭이 줄어든다. 민정은 모든 알림을 끄지 않고 **"직접 제안만 즉시 알림"** 으로 설정해둔다.

## 4. 솔루션 접근법 (How - 개괄)

### 접근 방식
> **"발신자 투명성(MVP) → 추천 이유 공개(V1) → 피드백 루프와 알림 세분화(V2)"** 3단계로, 복잡한 알고리즘 개선 없이 레이블링·카피·단순 피드백만으로 신뢰를 회복한다.

### 핵심 아이디어
1. **발신자 타입 배지 (MVP)**
   - `🤖 AI 추천` — 리멤버 AI 자동 매칭
   - `🧑‍💼 헤드헌터 제안` — 서치펌/헤드헌터 직접 선택
   - `🏢 기업 인사팀` — 기업 담당자 직접 제안
   - 푸시 타이틀, 알림함 리스트, 상세 상단 세 표면에 동일 배지 일관 적용
2. **AI 추천 disclaimer + 버튼 문구 분기 (MVP)**
   - AI의 경우 상세 상단 1줄 안내: *"리멤버 AI가 프로필 기반으로 추천했어요. 기업의 직접 제안이 아닙니다."*
   - 버튼: AI는 "지원하러 가기", 헤드헌터/기업은 "제안 수락하기"
3. **추천 이유 카드 (V1)**
   - "이 제안을 받은 이유" 2~3개 항목 노출 (`프론트엔드 경력 5년+`, `React 경험`, `B2B SaaS 산업군`)
   - 매칭 근거가 약하면 내부 점수를 낮춰 노출 순위 조정
   - 확실한 근거만 표기, 불확실한 근거는 숨김 + "이 정보가 맞지 않나요?" 피드백 버튼
4. **제안별 "관심 없음" 피드백 (V1)**
   - 이유 선택: `직무 불일치` / `연차 불일치` / `산업군 불일치` / `이미 경험한 회사` / `보상 정보 부족`
   - 선택된 이유를 추천 알고리즘 개선 데이터로 저장 (주간 배치 반영)
5. **알림 설정 세분화 (V2)**
   - 통합 "제안 알림 ON/OFF"를 3분할: AI 추천 / 헤드헌터 / 기업 각각
   - 타입별 수신 방식 선택: "즉시 알림 / 주간 요약 / 끄기"
   - 기본값 전부 ON, 기존 OFF 사용자는 OFF 유지 마이그레이션

### 기술적/디자인적 고려사항
- 제안 payload에 `sender_type` enum 추가(`ai_recommend` | `headhunter` | `employer`). 단일 switch로 템플릿 분기
- 출처가 불명확한 과거/파트너 제안은 `추천 포지션`으로 표시하여 직접 제안 라벨 오염 방지
- iOS 푸시 타이틀 78자 내에서 이모지 배지 + 포지션명 + 회사명 잘리지 않도록 카피 테스트. 고정 포맷: `[배지] [포지션명] — [회사명]`
- 추천 근거는 사용자 노출 가능한 문장으로 변환하는 템플릿 레이어 필요 (raw feature vector 노출 금지)
- A/B 테스트: 배지 유/무, disclaimer 유/무 2x2 cell 중 최소 2개 비교. 10% 롤아웃 → 50% → 100%

5주차 셀프 리뷰에서 v1 MVP 6개 항목이 "실험 인프라(①payload 필드·⑤fallback 로직·⑥A/B 플래그)"와 "사용자 노출 UX(②~④배지·disclaimer·버튼 분기)"로 섞여 있다는 점을 확인했다. v2에서는 **선행 작업**과 **사용자 노출 작업**을 명시적으로 구분해, 선행 작업이 완료되기 전에는 10% 롤아웃을 시작하지 않도록 순서를 고정한다.

| E. 기업 응답 지연 시 선제 팔로업 | 수락 후 7일+ 무응답 대응 | 6 | 5 | 5 | 150 | V2 |
| F. 매칭 알고리즘 전면 개선 | AI 추천 품질 자체 개선 | 10 | 5 | 2 | 100 | 보류 |

### 선택한 아이디어
**A를 MVP, B+C를 V1으로 묶는다.** A는 Confidence 8의 근거가 탄탄하다: (1) 구조적 원인 규명 완료("포지션 제안" vs "지원하러 가기" 불일치), (2) 21명이 공감한 Play 리뷰 + brunch 분석글 존재, (3) 알고리즘이 아닌 UI 레이블링이라 실험 효과가 즉시 지표로 잡힘. 5주차 벤치마킹에서 같은 도메인의 원티드가 스카웃/지원을 구조적으로 분리하고, LinkedIn Jobs도 Promoted/Top match 라벨을 운영 중임을 확인 — 업계 검증된 패턴이라는 추가 근거가 붙어 Confidence 8의 뒷받침이 한 겹 더 두꺼워졌다.

B(추천 이유 카드)를 V1으로 함께 묶는 이유는 **리스크 1("AI 라벨이 붙으면 클릭률 단기 하락")의 직접 완화책**이기 때문. 라벨만 노출하고 근거를 가리면 "AI 추천=스팸" 학습이 일어날 수 있지만, 근거가 함께 보이면 "이 AI가 나를 보고 있다"는 신뢰로 전환 가능. C는 B의 데이터 루프를 닫는 쌍으로 동반 투입.

### 선택하지 않은 아이디어
- **D (V2)**: A+B+C로 "신뢰 구조"가 자리잡은 뒤에 붙여야 의미 있음. 지금 분할하면 사용자가 배지 체계 자체를 모른 채 설정만 복잡해짐
- **E (V2)**: 운영팀·CS 인프라 의존이라 별도 PRD 규모
- **F (보류)**: 근본적 해결이지만 AI Lab 장기 로드맵 영역. 한 스프린트 안에 끝나지 않고 본 PRD의 "투명성" 초점과도 어긋남

## 7. 리스크와 대안 (Risks)

### 리스크 1: AI 추천 라벨이 붙으면 단기 클릭률·지원 전환율이 하락한다
- **시나리오**: "헤드헌터 직접 제안"으로 믿고 열던 사용자가 "AI 추천"임을 알고 무시 → 단기 지원 수 하락 → Revenue 팀 반발
- **완화**: V1 "추천 이유 카드"를 **MVP 직후 빠르게 연결**해 "AI 추천 = 스팸" 인식이 굳기 전에 근거를 제공. A/B 데이터로 단기 손실과 장기 Retention(알림 OFF 감소) 트레이드오프를 수치로 제시. 대체 카피("🔍 내 프로필 기반 매칭", "✨ 맞춤 포지션 추천")를 MVP 내 A/B 후보로 병행
- **수치 트리거 (5주차 추가)**: AI 추천 상세 진입 → 긍정 액션률이 **기존 대비 ▼20%p 이상**이면 V1 추천 이유 카드 투입을 예정보다 앞당김(1스프린트 → 1주). ▼10~20%p 구간은 2주차 재평가, ▼10%p 미만이면 계획대로 V1 진행

### 리스크 2: "AI 발송 인정"이 법적·홍보 리스크로 번진다
- **시나리오**: 이전까지 암묵적이던 AI 자동 발송을 명시적으로 노출 → "그동안 속여온 것을 자백"이라는 역풍
- **완화**: 출시 커뮤니케이션을 "사용자 피드백 반영, 투명성 강화 업데이트"로 포지셔닝. 리멤버 블로그/공식 계정에서 선제적으로 설명하여 내러티브 선점. **배포 1주 전 Legal + PR 팀 리뷰를 필수 단계로 공식화** (5주차 추가)

### 리스크 3: 기존 제안 데이터의 출처 구분이 불완전
- **시나리오**: 과거 데이터·일부 파트너 연동 제안은 AI/직접 경계가 모호
- **완화**: 출처 불명확 데이터는 `추천 포지션`으로 표시, 직접 제안 라벨은 검증된 데이터에만 사용. 2~3개월 내 데이터 정합화 프로젝트 별도 킥오프
- **가드레일 (5주차 추가)**: `sender_type` 분포 주간 대시보드 관찰, fallback "추천 포지션" 비율이 전체 제안의 **30%를 넘으면** 데이터 정합화 프로젝트를 V1 착수 전에 끼워 넣음

### 리스크 4: 추천 이유가 부정확하면 오히려 신뢰를 잃는다 (V1)
- **시나리오**: "프론트엔드 경력 5년"이라 표시했지만 실제는 백엔드 경력인 경우, "시스템이 나를 모른다" 인상 강화
- **완화**: V1 초기엔 확실도 높은 근거만 노출(프로필에 명시적으로 기입된 값만). 불확실 근거는 숨김 + "이 정보가 맞지 않나요?" 피드백 버튼. 피드백률이 10% 넘으면 근거 표시 중단 후 품질 개선

### 리스크 5: 카피/배지가 iOS/Android 길이 제한 초과
- **시나리오**: 이모지 배지가 푸시에서 잘려 포지션·회사명이 사라짐
- **완화**: 배지 최소 문자수(이모지1 + 키워드 2~3자: "AI추천", "헤드헌터", "기업"). iOS/Android 실기기 푸시 시뮬레이션 QA 필수

### 리스크 6: Revenue 팀이 단기 지원 수 하락 우려
- **시나리오**: 투명성 강화로 AI 추천 지원 수가 단기 감소 → Revenue 팀 KPI 충돌
- **완화**: 단순 지원 수가 아니라 **상세 진입 후 긍정 액션률 + 알림 유지율 + 제안 응답률**을 함께 본다. "장기 응답 가능한 활성 인재 풀 품질 방어"가 B2B NRR의 선행 지표임을 설득

## 핵심 포인트 요약
이 PRD는 채용 제안의 **양** 을 늘리는 문서가 아니라, 사용자가 제안을 **신뢰** 할 수 있게 만드는 문서다. 리멤버 Revenue의 기반은 "응답 가능한 활성 인재 풀의 품질"이고, 그 풀을 지키는 가장 저비용 수단은 매칭 알고리즘을 고치는 것이 아니라 **발신자 출처를 드러내고 추천 근거를 공개하는 것** 이다. MVP로 출처 라벨링, V1으로 추천 이유·피드백 루프, V2로 알림 세분화—세 단계가 순서대로 붙을 때 비로소 "AI 추천 = 스팸" 학습을 역전시킬 수 있다.

### 참고 서비스 1: [원티드 — 스카웃 제안 vs 지원 유도 분리](https://www.wanted.co.kr/)
- 어떻게 풀었는지:
  원티드는 "스카웃"과 "지원"을 페이지·UI·문구에서 명확히 분리한다. 스카웃은 담당자가 프로필을 열람해 직접 메시지를 보내는 구조이고, 사용자는 "누가 내 프로필을 봤는가"를 별도 탭에서 확인할 수 있다. 채용 공고 쪽에서는 매칭 점수(%)를 공개해 "왜 이 공고가 나에게 추천되는지" 가늠할 수 있게 한다. 리멤버 사용자 리뷰에서도 "원티드에서 탈락한 기업으로부터 리멤버 AI 자동 제안을 받아 수락했다"는 표현으로 **원티드를 기준점 삼아 리멤버의 투명성 부족을 지적**하는 글이 반복된다.
- 내 PRD에 반영할 점:
  "스카웃"과 "지원 유도"를 구조적으로 분리하는 원티드의 해법은 MVP 발신자 배지 3단계(🤖 AI 추천 / 🧑‍💼 헤드헌터 / 🏢 기업 인사팀)와 동일한 접근이다. 같은 도메인의 직접 경쟁자가 이미 이 해법으로 운영하고 있다는 점은 ICE A안 Confidence 8의 업계 근거를 한 단계 더 두껍게 한다. 매칭 점수 공개는 V1 "추천 이유 카드"의 UX 방향성(근거를 숫자·태그로 사용자에게 노출한다)에 정합.
- 차별화할 점:
  원티드는 "매칭 점수 83%" 같은 단일 숫자로 근거를 압축 노출하지만, 리멤버는 동일 방식을 따라가기보다 **사람이 읽고 납득할 수 있는 문장**(`프론트엔드 경력 5년+`, `React 경험`, `B2B SaaS 산업군`)으로 풀어주는 방향을 택한다. 리멤버 사용자는 원티드 사용자보다 이직 빈도가 낮고 수동적 수신자이므로, 숫자 점수보다 "왜 그렇게 매칭했는지"를 서술로 보여주는 편이 신뢰 회복에 더 적합하다고 판단.

### 참고 서비스 2: [LinkedIn Jobs — Promoted 라벨 + "Skills you have" 카드](https://www.linkedin.com/help/linkedin/answer/a521205/find-and-save-jobs-on-linkedin)
- 어떻게 풀었는지:
  LinkedIn Jobs는 각 공고 카드에 `Promoted`(광고), `Top match`(매칭), `Easy Apply`(간편 지원) 같은 라벨을 노출해 **사용자가 공고를 열기 전부터 맥락을 구분**할 수 있게 한다. 공고 상세에서는 "Skills you have: 6 of 8" 또는 "You meet X qualifications" 카드로 매칭 근거를 명시적으로 공개한다. 즉 라벨링(MVP 스타일)과 근거 공개(V1 스타일)가 한 제품 안에서 공존.
- 내 PRD에 반영할 점:
  MVP 발신자 배지 3단계는 LinkedIn의 공고 라벨 시스템과 같은 기능 — **이미 글로벌 규모에서 검증된 UX 패턴**이라는 점이 Confidence 8 근거를 강화한다. V1 "추천 이유 카드"의 "Skills you have" 컴포넌트는 **프로필에 명시적으로 기입된 값만 근거로 노출**하는 방식의 직접 모델이다. 리스크 4(추천 이유가 부정확하면 오히려 신뢰 훼손)의 완화책 "확실한 근거만 표기"는 바로 이 LinkedIn의 설계 철학을 따라간 것.
- 차별화할 점:
  LinkedIn의 `Promoted`는 광고 vs 유기의 구분(비즈니스 맥락이 명확)이지만, 리멤버의 `🤖 AI 추천` vs `🧑‍💼 헤드헌터`는 **"나를 얼마나 알고 보낸 것인지"라는 감정 요소**가 얽혀 있다. 따라서 카피 톤을 LinkedIn처럼 드라이하게 가져가면 "자백"처럼 받아들여질 수 있어(리스크 2) 더 부드러운 카피("내 프로필 기반 매칭")를 A/B 후보로 병행 테스트해야 한다.

### 참고 서비스 3: [Netflix — "Because you watched X" 추천 근거 노출](https://about.netflix.com/en/news/how-netflix-s-recommendations-system-works)
- 어떻게 풀었는지:
  Netflix는 개인화 추천에 "당신이 시청한 X 때문에" 또는 "당신이 좋아한 Y와 비슷한" 같은 **한 줄짜리 근거**를 각 추천 row에 붙인다. 추천 알고리즘 자체는 블랙박스지만, 사용자는 "왜 이게 내게 왔는지"의 최소한의 단서를 항상 받는다. 이 작은 장치 하나가 "시스템이 나를 안다"는 인상을 만드는 핵심 UX.
- 내 PRD에 반영할 점:
  V1 "추천 이유 카드"의 UX 원조 사례. 복잡한 피처 벡터를 노출하는 것이 아니라, **사용자가 자기 프로필에서 이미 아는 단서**(`React 경험`, `B2B SaaS 산업군`)로 근거를 재구성하는 방식. 사용자가 "아 그래서 왔구나"라고 납득하는 최소 설명 수준을 Netflix가 정립했다.
- 차별화할 점:
  Netflix는 저관여 콘텐츠 소비(거절 비용 = 그냥 스킵)이지만, 리멤버는 고관여 이직 결정(거절 비용 = 기업 관계·시간·감정). 따라서 근거의 **검증 가능성**이 훨씬 더 중요하다. Netflix는 "비슷해서 추천"이라는 모호한 근거도 허용되지만, 리멤버는 프로필에 명시적으로 기입된 사실만 근거로 써야 하며 불확실한 근거는 숨겨야 한다 — v1 리스크 4 완화책 "확실한 근거만 노출"이 바로 이 차이에서 나온다.

## v1 → v2 변경 사항 (5주차 추가)

### 셀프 리뷰에서 발견한 구멍

1. **참고 자료 감상평이 비어 있었다**
   4주차 제출 시 섹션만 만들어두고 내용을 채우지 못했다. v2에서 Tumta의 리뷰 분석 글을 기반으로, 이번 PRD의 솔루션이 왜 "매칭 알고리즘 개선"이 아닌 "레이블링과 카피"가 되었는지를 VoC 분석 방법론 관점에서 정리.

2. **KPI 베이스라인 수집 계획이 모호했다**
   v1은 "베이스라인 수집 필요"라고만 적혀 있어, 언제·어떻게·누가 측정할지 불명확. v2에서 실행 계획을 다음으로 구체화:
   - **MVP 배포 2주 전부터** "알림 OFF 전환율 / 제안 알림 관련 부정 리뷰 키워드 필터 쿼리 / 제안 상세 진입 후 긍정 액션 funnel"을 Revenue·CS 팀 운영 대시보드에 선배치
   - **최소 2주간 현황 수집** → MVP 10% 롤아웃 집단 vs 베이스라인 집단을 주 단위로 비교
   - 측정 주체: Revenue 팀이 ownership, Product에서 funnel 설계를 보조

3. **리스크 1의 대응 트리거가 정성적이었다**
   v1은 "단기 클릭률 하락 시 추천 이유 카드를 빠르게 연결"이라고만 적혀 있어 "빠르게"의 기준이 없었다. v2에서 수치 트리거로 명시:
   - AI 추천 상세 진입 → 긍정 액션률이 **기존 대비 ▼20%p 이상**이면 V1 추천 이유 카드 투입을 예정보다 앞당김 (1스프린트 → 1주)
   - ▼10~20%p 구간은 모니터링 후 2주차에 재평가
   - ▼10%p 미만이면 계획대로 V1 진행

4. **"AI 추천" 카피가 단정적 — 리스크 2(법적·홍보)와 충돌 여지**
   대체 카피 후보가 Open Questions에만 있어 배포 직전에야 결정하는 구조였다. v2에서 **MVP 내 A/B 대상으로 3종 카피**("🤖 AI 추천" / "🔍 내 프로필 기반 매칭" / "✨ 맞춤 포지션 추천") 명시. 배포 **1주 전 Legal + PR 팀 리뷰**를 필수 단계로 공식화.

5. **"추천 포지션" fallback 비율이 관리되지 않음**
   v1은 출처 불명확 데이터를 "추천 포지션"으로 라벨링하도록 설계했지만, 이 비율이 전체의 70%를 차지하면 배지 시스템 자체가 무의미해진다. v2에서 가드레일 추가:
   - **fallback 비율이 전체 제안의 30%를 넘으면** → 데이터 정합화 프로젝트를 V1 착수 전에 끼워 넣음
   - 측정: `sender_type` 분포를 주간 대시보드로 관찰

6. **MVP 범위가 "측정 인프라 vs 사용자 노출" 기준으로 섞여 있었다**
   v1 MVP 6개 항목 중 ①(payload 필드 추가), ⑤(fallback 로직), ⑥(A/B 플래그)는 실험 인프라이고, ②~④는 사용자 노출 UX이다. v2에서는 **선행 작업**(payload·fallback·A/B 플래그)과 **사용자 노출 작업**(배지·disclaimer·버튼 분기)을 명시적으로 구분 — 선행 작업 완료 전에는 10% 롤아웃 불가.

### 벤치마킹으로 강화한 부분

- **원티드의 스카웃/지원 분리** 사례를 근거로, A안 발신자 배지(AI/헤드헌터/기업)가 이미 같은 도메인 경쟁자에게서 검증된 패턴임을 확인. ICE A안 Confidence 8의 근거에 "직접 경쟁 서비스 사례"를 추가.
- **LinkedIn Jobs의 Promoted 라벨 + Skills you have 카드** 사례를 근거로, V1 추천 이유 카드의 "프로필에 명시적으로 기입된 값만 노출" 설계(리스크 4 완화책)에 글로벌 스케일의 모델을 확보. V1 Confidence 근거가 "합리적 가설" → "검증된 패턴 적용"으로 강화.
- **Netflix의 "Because you watched X"** 사례로 V1 카드 구조를 "피처 벡터 노출"이 아니라 "사용자가 이미 아는 단서로 근거 재구성"으로 확정. 이 설계 원칙은 리스크 4(추천 이유 부정확이 신뢰 훼손)와 직접 대응하는 장치이기도 하다.
